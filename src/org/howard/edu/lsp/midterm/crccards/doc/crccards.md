# CRC Card Explanation – Library Lending System

Library collaborates with Book because its CRC responsibilities ("maintain books; add and find books; coordinate borrowing/returning; retrieve books by criteria") can only be carried out by asking Book objects for their ISBN, author and availability and by delegating state changes to `Book.borrowBook()` and `Book.returnBook()`. Book's responsibilities ("store book information; maintain availability; validate borrowing/returning; provide book details") are entirely about its own state, so it needs no knowledge of Library, which is why its Collaborators entry is "None". Keeping the dependency one-directional means Book stays simple and reusable on its own (a standalone Book can still be borrowed and returned), and changes to how the Library stores or searches books never affect Book. The three-book limit belongs to Library because it is a rule about the collection as a whole, not about any single book: one Book only knows whether it is available and cannot know how many other books are currently out. Library already "coordinates borrowing/returning" and owns the full set of books, so it is the only class with the information needed to "enforce the borrowing limit" before delegating the borrow to a Book.
